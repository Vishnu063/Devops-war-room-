# CI and controlled delivery

`.github/workflows/novacart-ci.yml` runs on application PRs, main pushes and manual dispatch. It installs from lockfile with Node24, installs matching Chromium, runs static/unit/API/real disposable PostgreSQL/browser/audit/recovery tests, builds app/operations/Nginx, exercises deployment acceptance and scans the runtime image with pinned Trivy action. Any failure stops the gate. Only sanitized summary JSON is uploaded, never raw fixture logs/screenshots/secrets.

The workflow uses pull_request, not pull_request_target. No production secrets are available to PR code. Actions and base images are pinned to verified commits/digests. Review upgrades through PRs; container scanning may uncover base-image findings even when npm audit passes.

`novacart-preview-release.yml` is manual-only, main-only and publish=false by default. The owner must approve GHCR via NOVACART_APPROVED_REGISTRY=ghcr.io and pre-create `novacart-preview` with required reviewers. A separate precheck queries environment protection and fails if required reviewers are absent/unreadable. The publish job waits on that protected environment, repeats acceptance/security gates, publishes a SHA-tagged image with the scoped GitHub token and records its immutable digest. No registry publish has occurred here. Plan/account restrictions may prevent required-reviewer environments; treat that as blocked, never weaken the check.

Remote deployment needs an owner-approved host/access/origin, least-privilege credentials and verified known-host identity. `novacart-preview-deploy.yml` is main/manual-only, checks existing required reviewers before obtaining secrets, validates the approved repository digest/target paths, verifies SSH known-host identity and invokes the checked-in rollout script. Both the workflow and the script reject configurations that enable preview/live orders or live payments. It updates only an already-configured preview. The rollout script is also available manually and updates only the explicitly configured NovaCart app/proxy, with post-deployment HTTPS smoke. It does not provision infrastructure, alter DNS, migrate the database, seed data, activate payments or enable live commerce. Production approval is a separate gate; there is no automatic production deployment.

Current environment cannot access api.github.com under its enforced network policy. Git fetch/push through the repository connection works, but GitHub PR/Actions/environment API access is blocked. Workflow syntax/local shell checks are not an executed GitHub Actions run. The owner must run these workflows after review and configure required branch checks and environment reviewers. No branch protection, GitHub secrets or environment settings were changed.
